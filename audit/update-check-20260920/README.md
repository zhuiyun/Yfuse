# 升级检查失败修复

诊断来源：用户提供的 `Yfuse-diagnostics-20260920-172600.zip`。
导出设备为 OPPO PLG110，Android 17 / API 37，应用版本 1.0.73（235）。
诊断文件仅作为故障证据读取。

## 根因

2026-09-20 的 7 次自动或手动升级检查均记录 `manifest_rejected`，
判定为 `RejectedNoKey`，随后记录 `check_failed`。
最后一次发生于北京时间 17:25:55。说明清单已经取得并解析，失败发生在客户端信任判断。
当前 HTTPS 清单读取返回 HTTP 200，发布版本为 1.0.74（236），无 signature 字段。

`docs/android-release.md`、Gradle 正式构建检查和发布脚本均支持不配置升级清单公钥。
但 `AppUpdateManager` 根据非 debuggable 标记，额外要求正式版必须有清单公钥，
导致按既定可选签名配置构建的正式版无法检查升级。
1.0.74 构建记录同样表明未配置清单公钥，因此现有线上 APK 也不是该问题的修复包。

## 修复

移除依赖 debuggable 状态的额外拒绝路径，检查、下载、安装和恢复统一使用公钥配置决定清单签名要求。
未配置公钥时使用既定升级源；配置公钥时仍拒绝未签名或签名无效的清单。
保留 HTTPS、不允许重定向、同源地址校验、大小和 SHA-256 校验、包名、版本及 APK 签名校验。

回归用例使用本次 1.0.73（235）与线上 1.0.74（236）的元数据，验证发现更新、相同版本不提示更新，
以及配置公钥后拒绝相同的未签名清单。升级模块的其余校验测试一起执行。

## 验证记录

升级模块 57 项测试全部通过（零失败、零错误、零跳过）；Android Debug Kotlin 编译及修改文件的 ktlint 检查通过。
完整结果及源码哈希见 `verification.json`，JUnit 原始结果保存在 `unit-results/`。

- `diagnostic-update-events.json`：从诊断包中提取的升级事件，不包含播放报告和其他功能日志。
- `verify.ps1` / `verify.log`：升级模块单元测试及 Android Debug Kotlin 编译。
- `check-format.ps1` / `format-check.log`：仅针对修改文件的 ktlint 检查。

本次修改源码，未打包、安装、推送或发布。现有客户端的拒绝逻辑已内置于 APK，
需要一次手动覆盖安装正式签名的修复版本，不能仅通过更新服务器清单解决。
