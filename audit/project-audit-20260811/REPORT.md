# Yfuse 全项目产品与体验审计

日期：2026-08-11

范围：Android 手机端、当前工作树源码、0.2.46 实机界面；按要求未进入播放页面。

参照：Forward、Infuse、SenPlayer、VidHub 的官方产品页、帮助文档与商店更新记录。

> 实施决定：后续改造按产品要求保留 `enableOnBackInvokedCallback=false` 和返回硬切，
> 不执行本报告中“恢复 Predictive Back/返回动画”的建议。新增共享元素只用于进入详情；
> 返回（包括快速返回）会主动抑制共享元素，减少动画模式也会禁用它。

## 结论先行

Yfuse 已经不是 MVP。它已有多服务器、跨服搜索、三播放引擎、直放/转码降级、Dolby/HDR、字幕与弹幕、离线、投屏、一起看、日历、账户同步和诊断工具，功能广度已接近成熟播放器。

当前最大的成熟度差距不是“页面或按钮还不够多”，而是四件事：

1. 播放失败、投屏、离线和跨服务器状态还没有形成可信的闭环。
2. 功能很多，但普通用户看不到“实际会怎么播、为什么降级、出错后怎么恢复”。
3. 搜索、下载、恢复和同步的边界场景不够完整。
4. 动效基础很好，但当前未提交的返回导航改动、开屏交接和图片入场会明显拖累完成度。

推荐把产品定位收紧为：**Android 上可靠、透明、善于多服务器管理的 Emby 高级客户端**。先把核心闭环做到比竞品更可信，再考虑 AI、多云盘和更多媒体源。

## 已有优势

| 领域 | 当前状态 | 判断 |
|---|---|---|
| 服务器与账户 | 多服务器、局域网发现、健康状态、迁移、加密云同步 | 功能强，但本地 token 与迁移包安全需补强 |
| 媒体库 | 继续观看、收藏、稍后观看、最近新增、分页、筛选、日历 | 已有成熟骨架 |
| 搜索 | 跨服务器并发、媒体库/年份/流派/状态筛选、演员与历史 | 入口强，相关度与分页仍是假闭环 |
| 播放核心 | ExoPlayer、mpv、MDK；直放、HLS、渐进转码与跨版本降级 | 技术深度是差异化优势 |
| 字幕与社交 | 字幕、弹幕、片头片尾、一起看、反应与聊天 | 明显强于多数单纯 Emby 客户端 |
| 离线与输出 | 断点续传、Wi-Fi only、PiP、Cast、MediaSession | 基础具备，远端控制和离线会话语义不完整 |
| 设计系统 | 语义化动效 token、减弱动画/透明、大号文字、玻璃材质 | 值得保留，需做 Android/TV 与性能收口 |
| 工程质量 | 约 90 个测试文件、539 个 `@Test`，发布流程包含 lint 和单测 | 缺 PR 全量 CI、UI/真机媒体矩阵与性能基线 |

## 竞品定位与 Yfuse 应学什么

- **Infuse** 的核心不是功能最多，而是播放能力说明、Direct/Library 两种大库策略、状态权威与输出限制说得很清楚。Yfuse 应优先学习“播放真值层”和同步规则透明度。[Infuse 媒体服务器说明](https://support.firecore.com/hc/en-us/articles/360006462093-Streaming-from-Plex-Emby-and-Jellyfin)、[播放设置](https://support.firecore.com/hc/en-us/articles/360015608854-Settings-Overview)、[Trakt 规则](https://support.firecore.com/hc/en-us/articles/4405098078743-Trakt-Sync)
- **Forward** 的优势是多来源聚合、线路、AI 字幕/搜索和丰富首页，但它更像聚合中心。Yfuse 近期不应跟进全部 AI 能力，应借鉴线路健康、离线队列、下一集预载和多版本聚合。[Forward App Store](https://apps.apple.com/us/app/forward-ai-media-hub/id6503940939?platform=vision)
- **SenPlayer** 强在可调手势、字幕/弹幕、跨服搜索、备用线路和播放中切换。Yfuse 已有不少底层能力，缺的是配置记忆、状态保持和普通用户可理解的控制面。[SenPlayer App Store](https://apps.apple.com/us/app/senplayer-media-player/id6443975850?platform=mac)
- **VidHub** 是四款中唯一明确覆盖 Android/Android TV 的产品，值得借鉴下载网络策略、外部 `/play` 协议和跨平台媒体管理，而不是照搬其云盘入口。[VidHub 官方指南](https://vidhub.okaapps.com/what-does-vidhub-do/)、[设置说明](https://vidhub.okaapps.com/settings-overview/)、[第三方播放协议](https://vidhub.okaapps.com/3rd-party-app-integration/)

Yfuse 的独特优势是 Android、多引擎和“一起看”。不要把这些优势稀释成又一个全来源文件管理器。

## P0：合并前或下一版本必须处理

| 项目 | 问题 | 建议 | 工作量 |
|---|---|---|---|
| 返回导航 | 当前工作树把 `enableOnBackInvokedCallback` 关掉，普通返回和 Predictive Back 都改为硬切，并删除方向测试 | 恢复 callback；前进、返回、预测返回分别定义；仅在“减少动画”时硬切；补左右边缘与无障碍测试 | M |
| 迁移凭据安全 | 服务器迁移文件和二维码本质上是包含 bearer token 的明文 JSON/GZIP+Base64 | 用口令派生密钥 + AES-GCM，或一次性设备握手；迁移码短时过期，导入后提示轮换 token | M |

| 画质闭环 | 生产入口固定 Auto，实际没有用户画质档位和动态自适应；转码只有粗粒度固定码率 | 增加原画/4K/1080p/720p/480p、Wi-Fi/蜂窝上限和实时降档；播放器显示实际 Direct Play/Transcode 与原因 | L |
| 投屏闭环 | 当前主要是发现、开始、停止；缺当前进度起播、远端 Seek/暂停/音量/结束/下一集和准确回传 | 建远端播放状态机；从当前进度起播；投屏进度成为回传源；断线恢复并声明字幕/容器能力 | L |

## P1：近期补齐的体验与功能

1. **把播放能力做成“真值层”**：按设备、当前引擎、容器、解码器、显示和音频路由生成动态 DeviceProfile；明确显示 Direct Play、Direct Stream、Transcode、HDR→SDR、Atmos→PCM、掉帧和降级原因。
2. **补可靠回传与恢复**：进度上报失败持久化重试；进程死亡后从安全快照自动恢复，而不是让用户去“我的 → 播放恢复与同步”。
3. **统一字幕管线**：即使当前没有字幕轨也能进入字幕页；统一服务器/内嵌/外挂 URL/本地/在线字幕；记忆语言、强制字幕、SDH、副字幕、延迟、位置与样式。
4. **搜索真正分页**：当前“相关度”实际按名称，且每台服务器最多 24 条。改用服务器相关度，保存 total/offset，支持加载更多、去重和精确标题权重；默认折叠 0 条与离线服务器。
5. **升级离线中心**：整季/未看集批量下载、版本/画质/预计空间、并发数、字幕与海报打包、看完自动删除、播放时暂停下载、网络恢复自动继续。
6. **加入 Emby Quick Connect/PIN**：手动地址与密码保留为高级路径；粘贴完整 URL 时自动拆协议、主机、端口和 base path。
7. **补 Collections/Playlists**：浏览、详情、添加/移除和排序；目前内部“稍后观看”不等于完整播放列表能力。
8. **合并“来源”和“播放版本”**：当前未提交改动新增资源卡和独立对话框，但已有版本面板也包含来源/文件/轨道。保留“最佳副本”能力，统一成一个“版本与来源”入口。
9. **建立新鲜度反馈**：缓存刷新失败时显示“离线内容 / 上次更新”和重试，不要把旧库存与旧进度伪装成实时结果。
10. **数据层分工**：偏好留 DataStore；媒体索引、搜索历史、下载、同步队列和缓存迁移到 Room/SQLDelight；凭据进 SecureStore。
11. **大屏与输入设备**：中屏改 compact rail，840dp 以上用 NavigationRail；建立 D-pad/键盘焦点环和焦点恢复；确认是否正式支持 Android TV 后再加 Leanback 入口。
12. **自动化质量门**：PR 跑 compile、全部单测、服务端测试、lint 与设计契约；增加 Compose UI/a11y、真机媒体矩阵、Macrobenchmark、JankStats 和进程恢复测试。

## P2：核心稳定后再做

- Trakt 双向同步，并公开 Emby/Trakt 冲突优先级、多账号隔离和离线合并规则。
- 标准化外部播放 Intent/deep link，传 URL、字幕、起播点并回传 finished/stopped 与进度。
- 帧率匹配、HDR 输出验证、反交错、音频 passthrough/downmix、夜间模式和更完整的诊断 HUD。
- 账户删除、设备/会话列表、全部撤销、忘记密码/恢复码与云数据导出删除。
- Widget、追剧提醒、日历通知；AI 字幕翻译和自然语言搜索放在最后，并明确隐私、费用和失败回退。
- Jellyfin、SMB/WebDAV、云盘等多来源聚合只在 Emby 核心稳定后评估。

## 动画审计

### 应保留

- `Motion` 的语义时长、统一曲线与可中断 spring。
- “减少动画”对轮播、列表、图片、滚动、播放器控制层和一起看动效的传播。
- 底栏选中胶囊的 spring、内存缓存图片瞬时显示、轮播在拖动/离屏/减少动画时暂停。
- 播放器已有的统一 chrome 显隐，不建议推倒重做。

### 必须调整

| 动效 | 当前问题 | 推荐参数 |
|---|---|---|
| 开屏 | 动画 1 约 1.9s、动画 2 为 2s；完成后仍可能看到转圈与半加载内容；浅色开屏状态栏图标对比不足 | 首次/大版本 900–1200ms，普通启动 350–600ms；减少动画 250–350ms 静态 Logo + ≤100ms 淡出；交接到结构化骨架，不叠中心 spinner |
| 返回导航 | 当前全局硬切并退出 Predictive Back，前进/返回语义不一致 | 详情前进 260–280ms、`+30dp→0`；普通返回 220–260ms；预测返回必须跟手；减少动画才 None |
| 海报网格 | 网络/磁盘图统一跑 550ms、12dp 动态 blur、1.05 scale，网格成本过高 | 网格只做 160–220ms alpha；Hero 可用 320–450ms alpha+轻 blur；内存缓存保持瞬时 |
| Dialog | 系统 Back 绕过已有退出动画；46dp/260ms 略重 | 系统 Back 走内部 dismiss；入场 240–280ms、24–32dp，退出 180–220ms；平板宽度限制 560–640dp |
| 剧集自动定位 | 首次打开长剧集会先显示顶部再飞到中部，全季页还会越过 Hero | 首次直接初始化目标位置；仅用户切换季/集时 180–240ms；横向当前集尽量居中 |
| 按压与焦点 | Tab 按下缩到 0.92 偏深；无键盘/D-pad focus-visible | Tab 改 0.96；焦点环 2dp、外偏 2–3dp，焦点缩放 1.02–1.04/120–160ms；减少动画仅关缩放，不关焦点环 |
| 详情 overscroll | 每个滚动回调启动协程更新 Animatable，120Hz 下有乱序和掉帧风险 | 拖动阶段同步状态，松手只启动一个 spring |

Hero 轮播的 6 秒停留、500ms 自动切换和显式暂停按钮可以保留；需要把 `Int.MAX_VALUE` 无限 Pager 的 TalkBack 语义改成真实“第 n 项，共 m 项”。

## 可访问性风险

- 浅色开屏上的状态栏图标、外观页关闭态 Switch 对比不足。
- 全局最小触摸目标是 44dp，而 Android 更适合 48dp；下载页和下一集控件仍有 28/36/38dp 的实际违规。
- 自定义 `pressable` 去掉系统 indication，但没有键盘、鼠标和 D-pad 焦点反馈。
- 无限 Pager 可能向 TalkBack 暴露十亿级页码。
- 大号文字叠加系统 fontScale 时，固定 54dp 底栏和若干单行行高可能裁切。

本轮没有启用 TalkBack、键盘/D-pad、深色模式或 600/840dp 设备，因此不能据此声明完整无障碍合规。

## 推荐路线图

### 0–4 周：稳定性与合并门槛

- 恢复 Predictive Back，重做导航 spec 和测试。
- 修迁移与本地 token 安全。
- 修原生引擎终止错误回退、离线原服务器身份和进度队列。
- 去掉开屏后的中心 spinner，降低网格图片动效成本。
- 建立 PR 全量 CI 与最小真机播放冒烟矩阵。

### 1–2 个月：核心体验闭环

- 画质档位、动态 DeviceProfile、播放真值/诊断 HUD。
- 完整 Cast 状态机、可靠进度回传和自动恢复。
- 搜索分页/相关度/错误分组，离线 WorkManager 与整季下载。
- 统一字幕、版本与来源入口；Quick Connect。

### 3–6 个月：扩展与差异化

- 大屏/TV、Collections/Playlists、外部播放协议、Trakt。
- 帧率匹配、HDR/音频输出策略与设备兼容矩阵。
- 在核心稳定后再评估 Jellyfin、多云盘和 AI 字幕/搜索。

## 证据限制

- 界面截图来自设备上的 0.2.46 release 构建；当前工作树还有 6 个未提交文件，其中返回导航、详情资源与剧集定位改动通过源码静态审查，未包含在全部截图中。
