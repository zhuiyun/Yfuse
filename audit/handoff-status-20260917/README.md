# 设备接力登录状态排查（2026-09-17）

## 现象与证据

用户已登录账号，但设备接力页同时显示“请先登录账号并连接接力服务”和“无法连接设备接力服务，请稍后重试”。原界面仅用心跳是否成功判断提示文案，控制器又将所有心跳异常替换为通用错误，导致服务异常被误解为未登录。

对当前账号服务 `https://47.112.219.60` 的匿名检查结果：

| 请求 | HTTP 状态 |
| --- | --- |
| GET `/api/v1/account/profile` | 401 |
| GET `/api/v1/account/handoff` | 404 |
| POST `/api/v1/account/handoff/heartbeat`（空 JSON） | 404 |

未读取或发送用户凭证。当前源码的接力接口先鉴权再处理请求，且由 `AccountRoutes.kt` 注册；线上返回 404 表明接力接口当前不可用。尚未检查线上进程或反向代理，不能仅凭该结果确定具体部署原因，也不能据此判断用户凭证是否有效。

## 客户端修复

- 独立记录账号状态，分别显示未登录、已登录正在连接、已登录但连接失败、已连接。
- 设备接力设置页和播放器面板使用相同状态文案。
- 保留受控的 HTTP 错误原因，区分服务接口不可用、凭证失效、权限不足和限流；不展示服务端原始响应内容。
- 保持一次凭证刷新重试上限；退出账号时取消未完成的心跳，服务恢复后清除连接错误。
