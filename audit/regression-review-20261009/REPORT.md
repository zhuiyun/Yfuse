# Yfuse 再次审查与回归验证

日期：2026-10-09。保留此前详情手势、可预测返回、自有后端隔离和全项目修复。本轮继续检查当前实现的取消、重建、身份、并发和失败恢复边界，修复确认缺陷；没有打包、修改版本、推送或部署。

自动化检查能证明具体场景下的行为，不能证明所有设备、服务器和媒体格式均没有问题。真机与平台验证的范围见文末。

## 本轮修复

| 模块 | 已确认的问题 | 修复与回归 |
| --- | --- | --- |
| 账号与云播放记录 | 错误响应解码把 `CancellationException` 包装成 401，调用方可能误认为认证失效并续期或退出账号 | 共用 `AccountErrorResponse`，保留取消传播和普通错误回退。两项真实 HttpClient 响应转换管线测试在修复前失败，证明错误确实存在 |
| 遥控与一起看传输 | 遥控连接吞掉接收通道异常及关闭原因的取消，可能把异常当正常结束，或等待无法完成的关闭原因 | 共用 `RelayFrameReader`，异常立即传播，只有正常结束才读取关闭原因；保留认证过期识别。六项文本、控制帧、认证和异常/取消回归 |
| 播放器配置重建 | Activity 重建沿用首次启动的播放意图，用户暂停后重建可能自动播放，原本暂停启动后点播放也可能恢复成暂停 | ViewModel 保留当前实际播放意图和进度，在呈现状态更新及配置销毁时保存；覆盖两种相反的播放意图变化 |
| 播放器媒体替换 | 新媒体等待 `recreate()` 时旧回调仍可写回旧位置，污染新影片的启动 | 新请求立即使旧恢复代次失效；状态、进度和销毁路径统一检查归属。覆盖 ready/pending 替换及迟到回调 |
| 播放准备与退出 | 准备阶段的可选盘片处理吞取消，旧准备结果在返回或换片后仍可写回并初始化播放器 | 准备任务可取消，发布时校验请求归属、退出状态和协程存活；有效替换释放旧 pending，退出动画开始即阻止初始化 |
| 离线视频与字幕 | 下载复制循环只检查业务状态，WorkManager/服务取消后仍可能继续读写整个响应；字幕 URL 解析还会吞取消 | 共用 `readOfflineChunk`，读前、读后、读取异常时检查协程；取消不写迟到数据，并沿既有 finally 释放资源。两项取消、异常、关闭行为回归 |
| 离线恢复与容量 | 视频已完成重命名、字幕尚未保存时取消，或重命名后索引写入失败，会将进度重置为消失的 partial 文件大小，临时漏算完整视频的存储占用 | 恢复和取消使用本地已完成视频的实际大小，发布后先记录成品再持久化索引；未完成文件仍按 partial 计费。覆盖实际文件重命名、索引 I/O 失败/取消、发布失败和容量边界；恢复继续只补字幕 |
| 跨服务器片源 | 模糊标题搜索没有匹配项时仍返回首条，可能把续集、不同年份改编或其他类型作品标成资源 | 删除任意首条兜底，保留 TMDB 精确查询的译名支持。两项 MockEngine 回归覆盖错误候选排除和译名保留 |
| 服务端 Trakt 授权 | 设备码网络调用期间没有预留容量，并发 begin 可突破上限、留下同会话重复授权，较旧请求迟到还能恢复旧状态 | 锁内预留容量，新请求使旧请求失效，失败/取消在 finally 释放。四项交错请求、容量、失败与取消回归 |
| 迁移码限流 | 表满时逐出仍有效的计数，可通过轮换地址重置保护；锁外采样时间乱序也会重置窗口 | 满载拒绝新身份，按各窗口自己的到期时间回收，锁内使用单调有效时间。三项容量、不同期限、时间乱序回归 |
| 日历签名 | 进程级签名缓存只包含 publication，不包含签名密钥；同 JVM 不同应用/密钥可复用旧签名 | 已签名缓存由 signer 实例持有。新增两个应用、两套密钥的实际验签回归 |

本轮新增 34 项 Kotlin 回归：客户端传输 8 项、手机共享/Android 18 项、服务端 8 项。将相同的取消语义和状态归属集中到小组件，保留现有用户操作及协议。

## 仍需验证的功能环境

- **系统与 TV 交互**：审查后段 ADB 出现一台 Android 9/API 28 的 SM-G973U，已将设备记录归档；本轮没有替换已安装应用。新版 Android 可预测返回、当前修复的实际配置重建、来电/锁屏/PiP、通知/TV 控制和投屏仍需使用包含本轮改动的 APK 真机验收。尤其在临时音频焦点丢失时发生重建，当前实现保守保持暂停；恢复播放的产品预期应在设备测试中确认。
- **真实网络与存储**：离线取消在阻塞读取返回后生效，已阻塞的读仍可能等待数据或既有 30 秒超时，不能保证瞬间中断连接。SAF 撤销、磁盘不足、代理断网、真实 Emby/Jellyfin/Plex、Trakt OAuth 及双设备接力/一起看需要隔离测试环境。
- **原生和 Harmony**：原生协调逻辑已补齐 Android 设备运行验证；真实播放引擎、媒体格式、解码与渲染集成仍需使用对应产物验收。Harmony 的 stdx/SDK/HAP 和设备验证缺口仍存在。
- **既有后续项**：renderer 的 DNS/网络出口隔离、播放上报持久化失败后的重启恢复仍需专项设计和故障注入，不能用本轮测试推定已经解决。验收步骤继续参照[上轮优化计划](../comprehensive-review-20261008/IMPLEMENTATION.md)。

本轮结论适用于记录的源码与自动化场景。只有设备、真实服务和平台验收补齐后，才能扩大功能验证的声明范围。
