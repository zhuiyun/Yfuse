# 下载轨道绘制与播放器状态边界 · 2026-09-10

本轮承接用户确认的下载进度轨道和播放器状态拆分，保留此前动效、字幕、图标及氛围光修改。

## 修改

- 下载轨道固定为原有全宽、4dp 布局，在绘制阶段读取进度、收起和流光相位。填充与收起不再改变子布局宽度。
- 使用原 AppShapes.track 轮廓，按实际宽度缓存路径；保留左右布局的 start 对齐、嵌套宽度的像素取整、流光渐变和完成圆点。填充比例额外限制在合法范围，避免弹簧过冲画出轨道。
- PlaybackRuntimeContent 承担播放状态订阅，初始化宿主不再直接读取 tick。换内核仅重建 collector，运行区的 remember 状态（含时间轴记忆）保持；新内核首个快照不会继承旧内核终态。
- 底部时间轴改用 PlaybackTransportState，仅包含位置、时长、缓冲位置、倍速、条目索引与按钮状态。诊断、轨道列表不再作为底部时间轴状态参数传入。
- 播放按钮使用 PlaybackButtonState，仅保留播放/缓冲、可跳转和上下集可用性；按钮模型不随播放位置变化。快进/后退回调通过最新状态引用读取位置，避免为缓存丢失时效性。
- 诊断绑定接收 State，通过 snapshotFlow 订阅变化，并继续使用原有合并队列和后台报告工作器；不在绑定组件的组合阶段读取逐 tick 快照。完整诊断仍保留给设置页和报告。

## 验证

- 新增 5 项回归：运行区 tick 隔离及换内核后的订阅/记忆；诊断与时间轴、时间轴与按钮的状态独立性；按钮在队列、播放状态变化时更新；下载轨道 RTL/取整、动画越界与完成端点。
- 本地 Compose Recomposer 测试实际验证宿主组合次数不随 tick 增长、旧源更新不再生效、新源当前值及时接管，运行区 remember 保持。
- 变更文件 ktlint、git diff --check、手机/TV 展示层边界检查通过。
- Android/TV 编译和测试、协议/服务端回归及 macrobenchmark 代码编译通过，构建耗时 4 分 19 秒。共 2,690 项测试，失败、错误、跳过均为 0：Android 2,448、TV 59、协议 8、服务端 175；后两项复用 Gradle 确认有效的已有结果。详见 `test-summary.json` 与 `feature-tests.log`。
- 新增 5 项测试实际执行通过；设计系统检查通过，日志见 `design-system.log`。
- 逐段比对运行区搬入组合边界前后的内容，除诊断绑定参数、新增作用域及格式化的大括号外，保留原有运行逻辑。

## 范围与限制

播放器运行区仍消费完整状态，用于网络恢复、投屏、同步、上报和控制层；本次建立状态读取边界及精简底部模型，没有宣称整个播放器无重组，也未对真实功耗或帧率作估计。运行区的大文件进一步拆分、海报模糊缓存与下一集倒计时插值不在本轮内。
