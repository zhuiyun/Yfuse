# 播放页面剩余问题修复

日期：2026-10-10。用户先要求列出问题，随后授权将列出的 7 项直接修复到项目。

## 修改范围

1. **跳转绑定原视频和输出会话。** 跳转队列同时记录视频、线路、版本、播放地址、内核及运行会话、投屏接收端和接收端队列位置。120ms 合并窗口结束后重新核对归属；换集、重试、切线路、切版本、切内核、转码、发起投屏、结束投屏和退出时取消待执行操作。已被替换的控制栏不能在拖动取消时提交原视频的目标，进度条也会随归属变化重新创建。
2. **投屏返回遵守本机播放条件。** 停止投屏的异步响应只有在本机视频和操作仍有效、接收端会话没有被替换时才能恢复。异常断开也核对该投屏会话对应的本机视频。统一通过 `WatchGatedPlayback.restoreLocalPlayback` 返回；房间成员不抢夺控制权，返回播放须通过 Activity 原有的前后台、屏幕状态和音频焦点检查。不能播放时保留返回位置并暂停，暂停状态的接收端不会请求播放。
3. **连续点击独立累计目标。** 同侧连续点击使用上一个目标计算下一步，避免内核迟报位置导致重复跳向同一处；正常播放超过目标时纳入新的进度。新的连击窗口与视频切换重新开始，不沿用旧目标。
4. **临时倍速只恢复原视频的暂停。** 在恢复播放之前保存长按的归属。松手时只对同一视频和输出恢复原暂停；自动换集、切输出、替换内核和取消操作清除临时倍速，不暂停新内容。连恢复播放立即换集的情况也不能让新一集继承上一集的暂停。
5. **投屏倍速入口与能力一致。** 当前投屏接口没有远端倍速命令，入口显示置灰的“倍速”，不显示本机速度冒充远端速度。无障碍说明提供不可用原因，已经打开的倍速菜单在投屏开始后关闭；回调也重新检查当前接收端状态，不写入本机选择或剧集记忆。
6. **一起看成员不能通过倍速间接修改本机。** 成员倍速入口置灰、关闭原菜单；操作只有在权限允许且播放门禁接受后才保存。曲目恢复效果在成员跟随期间停止发送本地请求倍速，交由房间同步负责，避免绕过门禁覆盖房间速度。
7. **持续跳转时保持控制栏。** 两侧长按、画面横向拖动和进度条拖动均阻止自动隐藏。交互结束后重新等待完整的隐藏时间。中央临时倍速仍沿用原有隐藏控制栏的体验。
