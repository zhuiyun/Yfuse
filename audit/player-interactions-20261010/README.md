# 播放页面交互检查与修复

日期：2026-10-10。用户确认需要扩大的是播放画面左右两侧的长按区域。

## 已完成的修改

1. **准备播放时可以直接关闭。** 原准备页关闭入口位于全屏过渡动画下面，获取播放信息较慢时可能一直被遮住。将过渡层放进准备页、保持关闭按钮在其上方，使用 `safeDrawingPadding` 避让横屏刘海和系统安全区，并统一为关闭图标。按钮沿用原有最小触摸尺寸。关闭会取消准备任务，防止退出后继续启动播放。
2. **播放过程中缓冲时，点击显示控制栏和关闭按钮。** 缓冲状态下重复点击会保持控制栏显示；隐藏状态的首次点击优先显示控制栏，不会延续前一次双击快进，也不会先选中弹幕。锁屏仍须先解锁。关闭面板后会重新计算控制栏隐藏计时。
3. **左右长按各占画面宽度的 40%。** 左侧连续快退，右侧连续快进，中间 20% 保留可选的临时倍速。双击仍按原来的三等分区域处理，中心双击暂停设置也保留。长按每 500ms 按现有 10／15／30 秒步长设置推进一次，显示累计移动秒数和目标时间，松手停止。
4. **连续跳转与取消。** 独立累计目标，避免内核位置上报延迟导致每次都跳向同一时间；不超过片头、片尾，也不会在未知时长时跳转。500ms 重复间隔大于原 120ms seek 合并窗口，让各次跳转可以实际到达本地内核或投屏接收端。松手、输入取消、第二根手指、换集、切换投屏、锁屏、打开面板、播放失败、失去一起看控制权或退出控制层都会停止后续长按跳转；换集和输出路线变化时也会恢复临时倍速。
5. **帮助和设置说明同步。** 说明左右 40% 区域、中央 20% 倍速区域、重复间隔、松手停止及共用的快进快退步长。

## 检查结果

- 运行阶段的入场过渡、画面等待层本来就处于控制层下面；本次修正的是准备页的关闭入口层级。
- 运行阶段关闭按钮已有独立的最小触摸区域，不依赖可见圆圈尺寸。
- 锁屏、失败时的重试／返回、一起看访客权限、拖动结束提交、双指接管输入以及无障碍控制层显示时长已有独立处理，本次保留这些交互。
- 连续长按的计算和重复任务拆出 `PictureHoldSeek.kt`，复用原有 seek 发送路径，避免将定时合并逻辑再塞进 Compose 控制层。
