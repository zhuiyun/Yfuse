# 两份诊断日志的修复与验证

对应用户要求：全部排查并修复；特别关注 OPPO 手机观看《绿灯军团》时中文旧字幕不消失、不断叠加。

## 已落地的客户端修复

| 问题 | 修复 |
| --- | --- |
| PGS 旧句一直保留 | 将 FFmpeg 的无限结束时间视为“等下一展示集”，按同轨下一组的 PTS 截断上一组；同一组的多个矩形一起显示。 |
| PGS 清屏丢失 | JNI 保留成功解码的零矩形展示集，与“本包尚无解码输出”明确区分；使用实际组合段时间，支持 END 包晚到。 |
| 双字幕、预取、拖动后的残留 | 主副轨分别维护展示状态；未来事件到达时只修改时间区间，播放时钟到达后才替换/清屏；拖动和换轨清理旧代次。 |
| 普通内嵌字幕快速对白重叠 | 缺少容器时长时，用下一句的时间截断旧句；空文本清屏，同一时间的文本组仍可共存。ASS 的独立图层保留。 |
| DASH 分段字幕时间不一致 | 只将内嵌字幕从分段时间转为整片时间；外置字幕保留整片时间；ASS 渲染再转换回脚本时间。 |
| 原生模式下字幕触发无效引擎切换 | 原生专用模式不再因 ASS 自动请求不生效的 MPV 切换。 |
| 平台与增强探测串行耗时过长、退出后继续探测 | 同次起播的路由/媒体/解码器探测以及增强首开共用 30 秒单调时钟预算；取消实际 HTTP/数据源及 FFmpeg open/read，阻止迟到结果返回播放器；厂商阻塞探测使用有界工作线程。 |
| 连续探测偶发被误判为忙，导致 DASH 起播或切段失败 | 工作任务先完成资源清理并归还所属槽位，再通知调用方；按任务身份释放，避免上一任务误清下一任务的占用状态。 |
| 重试时旧解码器尚未释放就创建新实例 | 按实际子播放器复用增强路径；需要重建时等待旧 worker 完成释放，超时仍保留释放屏障，后续重试不能绕开。 |
| 解码器失败缺少可用证据 | 导出有界的解码器名称、错误类别、错误码和诊断标识，便于区分设备不支持与资源失败。 |
| 日历超时误报为存储写入失败、取消后一直等待 | 保留协程取消传播，查询预算耗尽使用独立事件；子任务取消时关闭结果通道，避免父任务无限等待；真实存储错误仍按原策略降级。 |
| 更新被缺公钥配置阻止、错误原因含糊 | 按用户后续要求移除缺公钥门禁：正式版和调试版均可正常检查、下载及恢复更新；6 个 CI 工作流支持不配置更新密钥。公钥可选，配置时仍校验清单签名，签名错误独立提示。 |
| 更新归档身份与恢复记录校验不足 | 安装前同时检查 APK 包名、实际版本与清单一致且高于已安装版本，并保留签名证书校验；恢复旧下载记录时重新应用当前版本的来源与可选清单签名规则。 |
| 诊断混合版本与卡顿上下文不足 | 历史条目记录版本、构建基线及进程来源；旧条目标明来源未知；字幕选轨/格式与替换/清屏计数、总帧数/观察时长加入诊断，计数窗口同步。 |

字幕内存达到上限时先回收过期图片。对于极端、交织很差的文件，不阻塞音视频队列；必要时舍弃远期字幕图片并保留清屏边界及降级计数。正常当前展示与最近的预取字幕优先保留。

## 仍需外部条件

- **更新服务可用性**：缺公钥已不再阻止在线更新；此修改没有向线上更新服务发布 APK/清单，实际检查和下载仍需要服务可访问且提供正确的版本文件。公钥仅是可选增强配置，见 `UPDATE_KEY_SETUP.md`。
- **服务端错误**：Emby/代理/CDN 的 403、鉴权拒绝、5xx 和连接超时，需要实际服务恢复或更新对应凭据；客户端修复不能让远端错误变为成功响应。
- **原设备与片源**：日志没有保存字幕格式/原始字幕数据，PGS 是已复现的确定代码缺陷，但仍需 OPPO 手机上用同一《绿灯军团》片源复测，才能确认用户现场全部症状消失。
- **界面卡顿**：日志不足以确认具体页面和 UI 根因。本次补充可信的总帧数及上下文，没有把观测改进描述为已消除所有卡顿。
- **厂商驱动边界**：不能强杀忽略中断的厂商 MediaExtractor/MediaCodec 调用。调用方会按预算退出，禁止迟到资源交给新播放器，并由原工作线程清理；没有宣称全部内核的完整首帧链都限定在 30 秒内。
