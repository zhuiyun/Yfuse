# 剩余动效补齐 — 2026-09-10

本轮按用户列出的七组剩余事项实施。没有连接手机、运行设备测试、签名打包、提交或上传代码。原有播放内核预读改动和其他工作区改动保留。

## 1. 播放器进入与退出

- 首页英雄卡片、媒体库英雄、详情播放／从头播放／选集入口登记海报来源。只保留媒体键、有效窗口矩形与图片 URL；不在全局保留 Activity、View、Bitmap 或坐标对象。
- 跨 Activity 使用一次性令牌，进入时将来源海报矩形移动到视频矩形，视频首帧就绪后 QUICK 淡出。等待首帧时保留明确的加载光球；错误时让位于错误界面。
- 图片按终点尺寸固定测量，动画只改变放置图层的位置、缩放、圆角和透明度，避免每帧变更图片解码尺寸。
- 显式返回先暂停播放，将海报反向回到仍有效的来源，完成后才释放播放器。来源已回收／不可见时用普通 Activity 返回；画中画和减弱动效不运行该形变。普通 Activity 转场作为回退，有来源形变时避免两套位移动画叠加。
- 以归一化坐标处理手机竖横屏边界，保留原有手机／平板方向策略。进程重建或过期令牌正常回退。

## 2. 骨架与懒列表

- `SkeletonHandoff` 保留便宜的旧骨架直到有限淡出结束，真实内容只维护一棵树。网格、详情、日历、我的、服务器和一起看连接区域接入。
- 首页、库首页和搜索是骨架与现有头部混排的列表；通过公共懒条目包装保留删除中的骨架，让它原地溶解。首页头部不跟随数据到达重新淡出。
- 公共到达时钟按可见条目登记顺序以 55ms 交错进入。长列表最多排列 13 个可见层级，1000ms 后所有内容均就位，后续滚入条目不会持续排长队。搜索独立揭示窗口为 1100ms，同样保留 55ms 步长。
- 手机功能页及播放器列表、剧集、聊天、贴纸等接入公共 `motionItem/motionItems`，使用动画根节点并保持原有 key/span/contentType 和惰性区间。一个懒条目内的多个节点继续沿主轴排列，避免简单 Box 包装造成重叠。减弱动效停用这些动画。

## 3. 搜索交接

- 结果身份包含实际结果、类型、筛选、排序及可见错误／人员结果；分页、新服务器结果和筛选等原地变化均可触发交接。仅输入未提交文字、loading/加载更多标志改变不重新隐藏结果。
- 请求结束时搜索胶囊分成带圆角的两个部分，留出真实间隙并复原；页面增加独立的雾状扫光带。既有 Dock 到搜索框的吸合入口保留。
- 隐藏路由和减弱动效完成事件直接消耗，返回时不补播；减弱透明度不绘制额外玻璃高光。

## 4. 播放器反馈

- 锁屏由有限可见性过渡交接，保留退出中的节点。剧集抽屉、弹幕搜索、设置和快捷面板、聊天面板，以及自动／手动跳过片段提示补上公共交接。
- 淡出中的公共控制层清除交互语义并拦截触摸，避免误点已关闭的动作；退出中的 BackOverlay 可停用返回处理。
- 中央反馈使用中心缩放原点；双击保留位置波纹并加入 BurstIcon 的方向图标。
- 文字字幕使用 QUICK 交叉淡入淡出，Core2 的 ASS／位图逐帧渲染不作为文字交接的键。保持已有双字幕顺序与外观控制。
- 保留已完成的倒计时插值、续播与音量反馈，不改动上一轮下一集预读和跳过片尾逻辑。

## 5. 选择控件

- 测量实际边界，设置和日历的分段指示器使用根 Tab 相同的前沿／后沿弹簧，支持不同文字宽度与 RTL。
- 公共 selectionColor 改用 Motion.settle；补齐媒体库分类、搜索筛选、日历日期芯片，以及播放器共用分段选项。

## 6. 页面加载语言

- 我的与服务器本地仓库首次数据到达前显示骨架；数据保留期间不人为制造加载时长。ProfileTabScreen 迁入 OfficialNavDisplay。
- 一起看连接区域有骨架到房间信息交接，原有成员与就绪状态反馈保留。
- 日历按日期使用 DisclosureContent，关闭后卸载日期正文，箭头从向右转 90° 到向下；首次定位按新的日期分组索引调整。

## 7. 预测返回

- BackOverlay 与栈页面的预测缩放目标改为 0.9。
- 栈页面圆角由 Navigation 3 的可寻址可见性过渡驱动，随返回进度变化；覆盖层保留取消回弹与圆角。

## 验证

最终本地验证：手机目标 2479 项、TV 目标 59 项 JVM 单元测试全部通过，合计 2538 项，0 失败／0 错误／0 跳过。新增 6 项回归覆盖 55ms 可见条目交错、搜索内容身份与过滤边界、跨方向海报坐标、令牌单次消费和来源回收。

手机 Release、TV Debug Kotlin 编译，设计系统使用检查、59 个改动文件的 ktlint、模块边界与改动空白检查均通过。最终 Gradle 构建耗时 3 分 52 秒。详见 `feature-tests.log` 和 `test-counts.json`。

代码证据见 `changed-files.txt`、`source-snapshot.json` 与 `diff/`。这些差异相对本轮开始时的文件，避免把工作区其他任务的改动计入本轮；新文件以 created 标记。

没有用本地 JVM 测试代替真机视觉验收。跨方向 Activity 的系统合成、Surface 与首帧实际观感、字幕叠放的最终观感仍需设备确认；本轮没有承诺所有设备上零黑帧或完全无缝。
