# 交互设计提案：从点按到跟手（2026-09-26）

原型画布（每组交互都能直接按、拖、捏，含慢放、减少动画和触感读数）：https://claude.ai/artifact/Ww5ZkNMcUdaZewcgqte1gC

本轮只做盘点和设计：没有修改 Kotlin 代码，没有构建或打包，所以不涉及 `version.properties` 和 `release-notes.txt`。基线 `bf8a9bf`（1.0.87 / 249）。画布里的海报和画面是占位色块，片名虚构；文中参数都是提案值，落地前按 [动画性能验证](MOTION_PERFORMANCE_20260908.md) 的方法在真机上测过再定。

**路径简写**：同 [动效与交互体验审查](MOTION_INTERACTION_REVIEW_20260924.md)。设计系统在 `composeApp/src/commonMain/kotlin/com/yfuse/core/designsystem/`，页面在同级的 `feature/<模块>/`，壳在 `app/`，TV 页面在 `tvApp/src/androidMain/kotlin/com/yfuse/tv/ui/`。

## 一、结论

1. **动效已经成体系，交互还停在“点一下，弹一个框”。** 令牌、「经典 / 静息」动效主题、减少动画门控都已到位（09-23、09-24 两轮之后）。但：
   - 长按统一弹居中对话框，而且只在部分列表有；首页“继续观看”的长按只有“查看详情”，和轻点一样。
   - 列表不能滑、不能长按拖选；删除类操作立即生效，Toast 没有“撤销”。
   - 播放器拖进度只有一档精度；缩略图只在拖进度条时出现。
   - 下载、投屏的进度离开应用就看不到；投屏要先开面板再选设备。
2. **提 5 组旗舰交互**：浮起菜单、跟手返回、播放器拖动 2.0、列表编辑（滑动 · 拖选 · 撤销）、实况与流转。另有 2 个次级原型（捏合网格与索引、TV 焦点视差）和 17 项小改进。
3. **尊重已有决定**：长按“扫描”替代 2× 倍速、底栏不随滚动收起、用系统画中画替代应用内迷你播放器，这三条都保留，理由见第六节。
4. **顺带发现 9 个问题**，其中“锁定控制挡不住双击和长按”是 P1，建议先修（第九节）。

## 四、原则

- **跟手，可打断。** 手指在哪，界面就在哪；松手时把速度交给后续动画，任何时刻都能反向。
- **从哪来，回哪去。** 从海报展开的页面返回时缩回那张海报；来源已不在屏幕上就退回普通返回。
- **手势是捷径，不是唯一入口。** 每个手势都对应一个看得见的按钮、一条读屏自定义操作和一个遥控器按键。
- **触感有语法。** 固定语义，按下不震，结果出来再震（第七节）。
- **跟随动效主题。** 「经典」给完整编排；「静息」和减少动画只保留跟手位移与淡入淡出，时长按 `CALM_DURATION_SCALE`；触感在所有档位保留。跟手位移是用户自己的动作，减少动画时也保留。
- **用到时再教。** 新手势只在第一次可能用到的地方提示一次，用过即失效，每天最多一条。

## 五、旗舰交互

### 5.1 浮起菜单（Lift & Slide）

**目标**：所有内容海报的长按行为一致。原地浮起预览，菜单就在手指下，按住滑选一次完成；同一套动作同时服务读屏、键盘、TV 和桌面快捷方式。

**时间轴**

| 时刻 | 表现 |
| --- | --- |
| 按下 | 现有 0.97 按压（`Motion.pressSpec`） |
| 150 ms | 继续下沉到 0.93，暗示还会发生什么 |
| 400 ms | 浮起：海报以弹簧 ζ0.8 · k380 变形为预览卡（256 × 158 dp：背景图、片名、年份时长评分、进度与剩余时间）；背景压暗 56% 并模糊；菜单项错峰 18 ms 出现；`LONG_PRESS` |
| 按住滑动 | 手指下的一项高亮，高亮本身不做动画；每换一项 `SEGMENT_TICK`；滑到预览卡上表示“打开详情” |
| 松手 | 在菜单项上：执行，结果回来后 `CONFIRM` 或 `REJECT`；在预览卡上：从预览卡展开进入详情；没有移动：菜单留下，改为点选 |
| 关闭 | 点遮罩、返回、下滑；预览卡弹回原海报 |

**菜单内容**（按上下文）

| 上下文 | 动作 |
| --- | --- |
| 继续观看 | 继续播放（剩余时间）、从头播放 │ 标记已看 / 未看、从“继续观看”移除 │ 收藏、稍后看、下载…、分享… |
| 电影 | 播放、从头播放 │ 标记已看 / 未看 │ 收藏、稍后看、下载…、一起看…、分享… |
| 剧集 | 继续 S2E5、全部剧集 │ 标记整季已看、追剧提醒 │ 收藏、下载下一集…、分享… |
| 单集 | 播放、标记已看、标记此前全部已看、下载、从这里开始多选 |
| 服务器卡片 | 打开媒体库、测试连接、设为当前服务器、线路、更多…（其余项仍在原对话框） |

**一套动作模型**：新增 `ItemActions(item, context): List<ItemAction>`，每项带 id、文案、图标、是否破坏性、是否可撤销和执行函数。“更多操作”面板（`DetailMoreActionsDialog.kt`）、浮起菜单、`semantics { customActions }`、TV 的 `TvDetailMoreActions.kt` 和桌面快捷方式都从这里取，“标记已看”只实现一次。

**实现要点**
- `LiftMenuHost` 挂在 `App.kt` 的浮层层级：底栏之上，`GlassDialog` 之下。模糊复用 `ModalGlass` 的背景录制；减少透明效果时换实色遮罩。
- 长按时只读一次来源海报的 `LayoutCoordinates`，不在滚动或拖动的每帧查询（09-24 审查 P1-8 的教训）。
- 按住滑选需要同一条指针流：`combinedClickable` 在长按之后不再报告移动。新增 `Modifier.liftable(item)`，内部用 `awaitEachGesture` 等到长按，再把后续坐标交给宿主；它取代现有 `pressable(onLongClick)` 在内容海报上的用法。
- 菜单优先放在预览卡下方，空间不够放上方；最多 8 项，超出滚动。
- 读屏：每张海报挂同一模型的自定义操作；菜单打开时 `paneTitle` = 片名，焦点落在第一项。键盘：右键、Shift+F10、菜单键。
- TV：长按确认键 600 ms 打开侧边面板（TV 已吞掉长按后的抬起事件），内容同一模型。

**减少动画 / 静息**：预览卡直接出现在目标位置，淡入 150 ms，不下沉、不缩放；模糊与触感保留。

**验证**：仪器测试覆盖长按 400 ms 出菜单、按住滑到第 N 项松手只执行一次、不滑动松手菜单停留、读屏自定义操作与菜单项一致、减少动画下没有缩放。

**工作量**：M–L。

### 5.2 跟手返回（Zoom back）

**现状**：`SharedMediaTransition` 只在向前时形变；预测性返回把退出页按线性时钟缩到 0.9，最后 90 ms 淡出（`OfficialNavDisplay.kt:180-194`、`:320-343`）；`BackOverlay` 缩到 0.9、透明度 0.8（`BackOverlay.kt:26-74`）。

**交互**
- **触发**：① 页面滚动在顶部时向下拖，移动 8 dp 后按 |dy| > 0.8 |dx| 判定；② 系统预测性返回。
- **下拉跟手**：p = dy ÷（0.45 × 屏高）；页面以按住点为中心缩放，scale = 1 − 0.3p，按住点保持在手指下；圆角 34p dp；底页从 0.95 恢复到 1，压暗从 50% 退到 0。
- **侧滑跟手**：scale = 1 − 0.12p，向滑动方向偏移 14p dp，纵向跟随 12%。
- **判定**：速度投影 170 ms，p′ =（dy + vy × 170 ms）÷（0.45 × 屏高），p′ > 0.3 提交；侧滑沿用系统的提交判定。
- **提交**：从当前矩形飞到来源海报的当前矩形，弹簧 ζ0.86 · k380，初速度 = 松手速度 ÷ 距离；内容在前 45% 淡出，海报图淡入。
- **取消**：同一弹簧回到全屏。

**边界**：来源滚出屏幕、列表刷新过、屏幕转过向或来源 key 不唯一时，退回普通返回（缩小淡出）。来源矩形由被点击的元素在点击时提交，返回时重新解析当前位置（09-24 审查 P2-34）。横向货架里的横滑归货架。

**触感**：越过 30% `GESTURE_THRESHOLD_ACTIVATE`；退回 `GESTURE_THRESHOLD_DEACTIVATE`（新增）；落定不震。

**减少动画**：跟手保留；松手后 150 ms 淡出，不做飞回。

**实现**：新增 `DragProgress`（位移、速度、进度，`project(ms)`、`rubberBand()`）；`OfficialNavDisplay` 给有来源的页面包 `ZoomBackContainer`，预测返回的进度与下拉进度走同一个几何函数；`SharedMediaTransition` 增加返回方向；`BackOverlay`（全部剧集、查看全部）一起接入。

**验证**：JVM 测几何函数在 p = 0 / 1 时的矩形，以及一组位移 × 速度的投影判定表；仪器测试覆盖 30% 以下松手回弹、以上返回、来源滚出屏幕时走普通返回。

**工作量**：M。

### 5.3 播放器：拖动 2.0

拆成 9 项，可以逐个上线。

| 项 | 做法 | 量 |
| --- | --- | --- |
| a. 普通文件章节 | 在 `playbackSegments()`（`Dtos.kt:685`）旁新增 `playbackChapters()`，取有名称的普通章节，接到三参数的 `playbackProgressMarkers`（`PlaybackProgressMarkersCompat.kt:10`，现在 `PlayerControls.kt:1021` 调的是两参数版本）。进度条按章节分段，缩略图卡片显示章节名，沿用 14 dp 磁吸 | S |
| b. 全程缩略图 | 把 `TrickplayImage` 卡片复用到画面横滑（`PlayerControls.kt:856-863`）、长按扫描和 TV 遥控快进（`TvRemoteInputController.kt`） | S–M |
| c. 精细与胶片条 | `StandardSeekBar`（`PlayerChromeRefined.kt:880-1228`）拖动时计算手指离开轨道的距离：34 dp 以内常速；34–84 dp 为 ¼ 速，改用相对位移；84 dp 以上为胶片条，按 trickplay 间隔逐格，每格 28 dp。分级滞回 6 dp；没有 trickplay 时只到精细档 | M |
| d. 扫描换挡 | 长按扫描时不再忽略横向漂移（`PlayerControls.kt:846`）：以按下点为原点每 44 dp 一档，停住 / ×10 / ×30 / ×60；手指没滑动时保留现有“3 秒后升到 30×” | S |
| e. 结束于 | 时间行显示“结束于 HH:mm”，按当前倍速计算，读屏可读 | S |
| f. 没听清 | 长按 ⟲10：倒回 10 秒，临时打开字幕（优先当前音轨语言），回到原位置后恢复原来的字幕设置 | S–M |
| g. 捏合填充 | 双指捏合在“适应”和“裁剪填满”之间切换，HUD 提示，沿用现有的按剧记忆 | S |
| h. 弹幕热度曲线 | 弹幕匹配成功后按 1% 片长分桶计数，平滑后画在进度条上方；只在控制栏可见时绘制，在绘制阶段读取 | M |
| i. 中间长按 2×（待定） | 中间三分之一长按临时 2×，左右每 44 dp 换挡 1.5 / 2 / 3×，松手恢复；手势设置里可关 | S |

**无障碍**：焦点在进度条时，方向键仍按 max(5 秒, 1%) 小步，Shift + 方向键逐格；读屏读出“结束于”；一起看的访客仍不能拖动。

**验证**：JVM 测分级状态机（含滞回）、换挡映射、章节解析（带 `MarkerType` 的 Emby 章节）、结束时间计算；仪器测试覆盖上移 90 dp 出现胶片条、松手落在所选格的时间。

**工作量**：M，合计。

### 5.4 列表编辑：滑动、拖选、撤销

**滑动**
- 横移超过 8 dp 且 |dx| > 1.2 |dy| 才算横滑，判定后锁定，否则交给滚动。屏幕左右 24 dp 留给系统返回手势，不从那里起横滑。
- 滑过 64 dp 松手，按钮停在 88 dp 处等点；滑过行宽 45%，或速度超过 0.9 px/ms 且位移超过 30%，松手直接执行。超过 80% 后加 0.25 的阻尼。
- 用法：剧集列表右滑“标记已看 / 未看”、左滑“下载 / 删除下载”；下载页右滑“暂停 / 继续”、左滑“删除”；我的内容左滑“移除”；线路列表左滑“删除”。

**拖选**：长按 400 ms 进入选择并选中当前行（`DRAG_START`），不松手上下拖动时选中起点到手指之间的连续一段，每多选或少选一项 `SEGMENT_TICK`；手指进入列表上下边缘 44 dp 时自动滚动，速度与深入距离成正比。标题栏保留“选择”按钮。底部操作栏：标记已看、下载、取消。

**撤销**
- `ActionToast` 增加一个操作槽，带 5 秒倒计时环（绘制阶段读取进度），读屏以 Polite 播报并提供“撤销”自定义操作。
- 能撤回的操作一律“先做，给 5 秒撤销”：界面立即更新，真正的删除在提示消失后执行；应用进入后台时立即提交，避免状态悬空。
- 追剧中心自绘的撤销行改用同一个组件。

**实现**：`SwipeActionsRow` 基于 `AnchoredDraggableState`（锚点 −88 / 0 / +88 dp）；`DragSelectState` 用 `awaitEachGesture` 处理长按后的拖动，配合 `LazyListState` 自动滚动；滑动操作同时写入 `customActions`。

**验证**：仪器测试覆盖横滑与竖滑的判定、超过执行线松手只执行一次、撤销后状态恢复、后台时提交。

**工作量**：M。

### 5.5 实况与流转

- **实况通知**（API 36+）：下载用 `Notification.ProgressStyle` 按集分段（完成、进行中、等待），投屏用节点标出章节并显示剩余时间，都带暂停和停止；按 Android 16 实况通知的条件申请常驻展示，具体条件以落地时的平台文档为准。Android 15 及以下保持现有通知（`OfflineDownloadExecution.android.kt:54-99`、`PlayerNotificationController.kt:56-100`）。一起看的状态变化频繁，留在应用内。Harmony 版对应实况窗，等 HAP 能构建后再接。
- **按住拖送**：按住投屏键 350 ms，最近用过的设备（Cast、DLNA 与同账号的 Yfuse TV，按最近使用排序）在投屏键下方竖排展开；拖到设备上松手即投送或接力，失败时 `REJECT` 并留在本机继续播。轻点投屏键仍打开原来的设备面板。接力沿用现有规则：接收方就绪后发送方才暂停（`HandoffController.kt:146-200`）。
- **接力横幅**：接收接力改为顶部横幅（接收 / 忽略），上滑关闭，不再用对话框打断。另一台设备正在播放时，也可以用同一横幅提示“在此继续”；这需要接力心跳带上正在播放的条目和位置，如果现在还没有，要一起补上。

**触感**：展开 `LONG_PRESS`；滑过设备 `SEGMENT_TICK`；投送成功 `CONFIRM`，失败 `REJECT`。

**无障碍**：设备同时列在投屏键的自定义操作里；横幅可聚焦，带“在此继续”“关闭”两个操作。

**工作量**：实况 M；拖送 M；横幅 S。

### 5.6 次级原型

- **捏合换密度与索引**：媒体库网格 2–5 列连续缩放，松手吸附；以捏合中心那张海报为锚，位置不跳；5 列时隐藏片名；每个媒体库记住列数。右侧索引按排序方式显示拼音首字母、年份或月份，字母变化时 `SEGMENT_FREQUENT_TICK`。标题栏 − / + 做同样的事。落点 `LibraryGridScreen.kt`，量 M。
- **TV 焦点视差与长按面板**：焦点移入时按方向给 ±8° 的 rotationY 冲量，弹簧 ζ0.55 · k260 回正，表面扫过一道 420 ms 的高光；只用 graphicsLayer 和渐变，不做模糊。长按确认键 600 ms 打开快捷操作。「静息」与减少动画只保留放大和描边。顺带让 TV 接入动效主题。落点 `TvUiComponents.kt`、`TvTokens.kt`、`TvApp.kt`，量 S–M。

## 七、触感语法

在 `HapticSignal` 里补 6 个语义，映射写在 `Haptics.android.kt`，连续刻度在实现里节流到 50 ms 一次。

| 时刻 | 语义 | Android 14+ | Android 11–13 | Android 8–10 | 状态 |
| --- | --- | --- | --- | --- | --- |
| 轻点主要按钮 | Tap | `VIRTUAL_KEY` | `VIRTUAL_KEY` | `VIRTUAL_KEY` | 现有 |
| 切换选择：tab、分段、开关行 | Select | `CLOCK_TICK` | `CLOCK_TICK` | `CLOCK_TICK` | 现有 |
| 长按浮起 | LongPress | `LONG_PRESS` | `LONG_PRESS` | `LONG_PRESS` | 现有 |
| 越过提交线：下拉刷新、下拉返回、滑动执行 | Threshold | `GESTURE_THRESHOLD_ACTIVATE` | `GESTURE_START` | `CLOCK_TICK` | 现有 |
| 退回提交线以下 | ThresholdRelease | `GESTURE_THRESHOLD_DEACTIVATE` | `GESTURE_END` | 不震 | 新增 |
| 滑过一格：菜单项、档位、章节、胶片格 | Tick | `SEGMENT_TICK` | `CLOCK_TICK` | `CLOCK_TICK` | 新增 |
| 快速刻度：索引条 | FrequentTick | `SEGMENT_FREQUENT_TICK` | `TEXT_HANDLE_MOVE` | `TEXT_HANDLE_MOVE` | 新增 |
| 进入拖动或拖选 | DragStart | `DRAG_START` | `LONG_PRESS` | `LONG_PRESS` | 新增 |
| 开关打开 / 关闭 | ToggleOn / ToggleOff | `TOGGLE_ON` / `TOGGLE_OFF` | `CLOCK_TICK` | `CLOCK_TICK` | 新增 |
| 操作成功，结果回来之后 | Confirm | `CONFIRM` | `CONFIRM` | `VIRTUAL_KEY` | 现有 |
| 操作失败或被拒 | Reject | `REJECT` | `REJECT` | `LONG_PRESS` | 现有 |

规则：按下不震，结果出来再震；只为手指下正在发生的事震，后台完成的事件不震；减少动画、读屏开启时触感照常。JVM 测试按 API 等级核对映射。

## 十二、实现记录（2026-09-26）

第十一节前两项已按建议实现。本节记录实际做法和与方案的差异。

### 12.1 画面中间长按：临时倍速

- **手势**：长按画面中间三分之一，按 2× 播放；按住左右滑动换挡，右快左慢，1.5× / 2× / 3×，每 44 dp 一档，往回滑要越过刻度 0.2 档才回退，手指停在刻度上不会来回跳；每换一档 `Tick` 触感；松手恢复原来的速度。左右两侧的长按扫描不变。
- **只作用于播放引擎**：临时速度只进 `PlayerTrackEffects`，不写系列记忆、不写偏好、不发给一起看房间。原来暂停着的，按住时播放，松手后重新暂停。
- **什么时候不生效**：锁定、面板打开、没有时长（直播、还没加载）、已播完或出错时静默不响应；一起看房客提示“房主控制播放”，房主提示“一起看时不能临时倍速”，投屏时提示“投屏时不能临时倍速”。按住期间进房间或开始投屏，临时倍速立即结束。
- **界面**：按下后控制层收起，顶部显示倍速胶囊（当前档加粗，另外两档变暗），读屏会播报；手势说明加了“长按中间”一行，并把“左半屏 / 右半屏”改为“左侧 / 右侧”，和实际的三等分一致。
- **与方案的差异**：方案写“手势设置里可关”。应用目前没有手势设置页，这次没有加开关。
- **顺带修复（第九节 P1）**：锁定后双击和长按仍会快进、暂停，现在锁定时画面只响应“解锁”。
- **实现要点**：长按触发后，`detectTapGestures` 会消费后续所有移动，而拖动识别器在越过触摸阈值前看到被消费的事件就放弃，所以换挡另用一个只读的指针观察者，只在临时倍速期间计算档位，不消费事件。
- **代码**：`PlayerSpeedBoost.kt`（档位、换挡滞回、拒绝原因、胶囊），`PlayerControls.kt`，`PlayerRoot.kt`，`Haptics.kt` 新增 `HapticSignal.Tick`（API 34+ 用 `SEGMENT_TICK`，以下用 `CLOCK_TICK`）。

### 12.2 浮起菜单

- **组件**：`LiftMenu.kt`（菜单模型、摆放与命中的纯计算、会话状态机），`LiftMenuGesture.kt`（`Modifier.liftable`），`LiftMenuHost.kt`（遮罩、预览卡、菜单）。宿主挂在 `App.kt` 根层：盖住页面、底栏和活动胶囊，在对话框窗口之下。
- **一条指针流**：`liftable` 放在 `pressable` 外层。长按之前只监听，列表先开始滚动就不会浮起；浮起之后在 Initial 阶段消费后续事件，所以海报自己的点击和外层列表都不会响应，手指坐标交给宿主做命中。
- **时间轴**：按住 150 ms 后再下沉到约 0.93；浮起时海报隐藏，预览卡从海报的位置和大小用弹簧（ζ0.8、刚度 380，`Motion.lift()`）展开到目标位置，尺寸在布局阶段逐帧插值，图片按每一帧的尺寸重新裁切，不做拉伸；有横版背景图时随展开淡入；文字在展开到 55% 之后淡入；菜单面板先出现，每行间隔 18 ms 依次出现。
- **操作**：滑到某行松手执行；滑到预览卡松手打开详情；没有移动就松手，菜单留下来点选。手指移动超过触摸阈值后才开始命中，防止手指停着不动、松手时误开详情。“离开页面”的操作（播放、打开）立即执行，浮层淡出；改状态的操作（收藏、标记已看、移除）等预览卡落回海报后再执行，结果出现在原位置。点遮罩或按返回关闭。
- **摆放**：预览卡以海报为中心，菜单在卡片下方，整体只平移到能放下为止，所以靠近屏幕底部的海报，菜单正好落在手指下面。窗口较矮但足够宽（横屏手机、平板）时卡片和菜单左右并排；都放不下时菜单滚动。
- **减弱动态效果 / 静息**：不下沉、不展开，预览卡直接出现在目标位置，整体淡入 150 ms；触感保留。
- **读屏和键盘**：每张海报都有同一组自定义操作；读屏的长按操作、键盘的菜单键和 Shift+F10 都能打开同一个菜单，焦点落在第一项。
- **替换范围**：
  - 首页“继续观看”“我的收藏”：继续播放（附剩余时间）/ 从头播放 │ 标记已看或未看、收藏或取消收藏。原来的长按弹窗只有“查看详情”。为此 `HomeStore` 新增 `PlayEntry`、`SetEntryFavorite`、`SetEntryPlayed`，播放标签带上起始位置。
  - 首页 TMDB 推荐栏和对应的“查看全部”页：播放、加入收藏。
  - 首页追剧日历：查看详情、打开追剧日历。
  - 媒体库网格：收藏、标记已看 │ 从播放列表或合集移除（原长按弹窗的内容，“查看详情”由预览卡承担）。
  - 统一媒体库：原来长按打开片源选择，现在菜单直接列出各服务器的片源，滑到哪个服务器松手就打开哪个。“N 个片源 · 选择”按钮仍然打开原来的片源弹窗。
  - 媒体库首页的播放记录和各库的海报栏原来没有长按，这次也加上：播放（经详情页选片源）、收藏。
  - 服务器卡片按决定不动。
- **与方案的差异**：遮罩只压暗 56%，没有背景模糊。对话框的背景录制会把同一窗口里的浮层也录进去，这里要模糊只能先把页面单独录一层，留到后续。方案中的“稍后看”“下载…”“分享…”“从继续观看移除”需要新的接口，这次没有做。TV 端没有接入，TV 上的海报不受影响。
