# 推荐刷新失败排查与修复（2026-09-08）

## 已确认的证据

- 用户反馈首页显示“推荐内容刷新失败”。旧实现会把各接口的 HTTP、网络、超时和解析错误丢弃为同一个空列表，无法从界面提示确定真实原因。
- 检查 1.0.44（206）正式 APK：DEX 内的推荐令牌与构建配置完全一致，Bearer 认证值存在，列表与条目的生成序列化器及反序列化实现也存在。没有发现签名打包漏令牌或 R8 裁掉序列化器的证据。
- 使用该正式包配置，只读访问 TMDB 官方认证接口成功；电脑端 16 路推荐接口检查均为 HTTP 200，且均包含有图片的条目。检查未输出令牌或响应正文。
- 当前 ADB 无连接设备。这些电脑端检查不能证明手机上的 DNS、TLS、代理或实际网络可达性正常；用户此次失败的具体原因尚未确认。

## 修复行为

- 保留逐接口失败类别，区分认证失败、拒绝访问、限流、超时、连接失败、数据异常、服务异常以及成功响应但无可用内容。
- 部分接口失败时，已成功返回的新条目仍可展示；失败栏目保留上次可用内容。完整成功的栏目按新结果替换，包括清除已成功刷新为空的旧栏目。
- 不用部分成功结果覆盖完整缓存，也不把部分刷新标为当天已完整获取，避免重开后跳过重试。
- 缓存读取、解码或清理失败不会阻止在线获取。取消仍向上传播，连续刷新和缓存写入继续遵守原有顺序保护。
- 保留单轮请求总预算与并发限制，失败提示说明实际类别。诊断记录保留安全分类与异常类型，不记录凭据或远端响应正文。

## 真机复核

1. 安装同正式签名的修复版本，打开首页并下拉刷新。
2. 若仍失败，记录新提示，并分别在 Wi-Fi 和移动数据上测试。
3. 在“我的 → 高级设置 → 问题诊断 → 导出诊断包”导出脱敏日志，定位 `tmdb/feed_request_failed` 与 `feature.home/recommendations_load_failed`。
4. 也可连接 S10 并开启 USB 调试；实时日志需在上述页面打开“输出到 Logcat”，默认关闭且一小时后自动关闭。

设备日志到位前，不将本次缓存与诊断修复表述为已解决手机的网络连接问题。
