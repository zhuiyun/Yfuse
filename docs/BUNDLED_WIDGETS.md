# 预置 TMDB 与影视推荐组件

Yfuse 在「组件与首页」中预置 **TMDB** 和 **影视推荐**，并提供两个同名页面。页面中的栏目使用单排横向海报，可继续在页面编辑器中调整栏目、样式和参数。条目提供 `type=tmdb`、`tmdbId` 和 `mediaType`，供应用统一进入影视详情页。

这两个组件在组件管理与内容来源选择中依次置顶，对应的预置页面在首页切换列表中依次置顶；排序仅作用于显示，不修改个人页面中的栏目顺序或默认首页。影视卡片点击进入应用默认详情页，附带来源链接时也保持同一入口。

## 来源与适配

- 来源：用户提供的 `CapyPlayer.apk`，包名 `com.feifeiduck.capyplayer`，版本 `1.1.7` / `117020`。
- APK SHA-256：`601a2cf31b7b61bd3485b4fcb3ee9e32b42b4947208e86904b6f56fb218fc569`。
- 两段 JavaScript 位于 `lib/arm64-v8a/libapp.so` 的 UTF-16LE 字符串中。TMDB 位于字节区间 `[690962, 707890)`，影视推荐位于 `[618002, 627238)`。
- 原始字符串、提取记录和适配生成器保存在 `audit/capy-builtin-widgets-20261023/`。源码注释和组件作者字段保留 CapyPlayer 来源。
- APK 的组件清单由原应用代码构造，原脚本没有 `WidgetMetadata`。Yfuse 补齐了与自身组件编辑器兼容的清单、参数选项及默认页面；清单不是从 APK 直接复制的 JSON。

运行资源：

- `composeApp/src/androidMain/assets/widgets/tmdb.js`
- `composeApp/src/androidMain/assets/widgets/movie-recommendations.js`

没有提取原应用的账号、认证密钥或原生播放器库。TMDB 保留 APK 另行配置的公开目录线路 `https://recommend.feifeiduck.com/tmdb/`，无需原应用账号或密钥；该线路异常时调用 Yfuse 的 `Widget.tmdb.get`，由宿主处理备用线路的认证。影视推荐保留原脚本使用的公开服务 `https://recommend.feifeiduck.com`。

## 内容

TMDB 共 9 个模块：热映/热播、综合趋势、热门、高分、按类型发现、按电视网发现、按制作公司发现、电影趋势、剧集趋势。其中电影/剧集趋势沿用原脚本中的兼容函数。支持中英文、分页、日/周趋势、电影/剧集类型与分类筛选；电视网和制作公司模块需要填写相应 TMDB ID。

影视推荐共 5 个模块、25 个不同榜单：

| 模块 | 榜单 |
| --- | --- |
| 电影推荐 | 豆瓣热门电影、豆瓣 Top 250、IMDb 热门电影、IMDb Top 250 电影、电影趋势、Trakt 最新 4K |
| 剧集推荐 | 豆瓣热门剧集、豆瓣全球高分剧集、豆瓣热门综艺、IMDb 热门剧集、IMDb Top 250 剧集、热门华语剧集、热门韩剧、剧集趋势、烂番茄热门剧集 |
| 动画推荐 | 豆瓣热门动画、热门国创动画、Bangumi 高分动画、MyAnimeList 高分动画、MyAnimeList 热门动画、即将播出动画 |
| 番剧日历 | Bangumi 放送日历、动画放送日历、巴哈姆特每周动画 |
| 流媒体趋势 | JustWatch 流媒体榜、电影趋势、剧集趋势、烂番茄热门剧集、Trakt 最新 4K |

部分榜单在不同模块中重复出现，去重后为 25 个。推荐服务按原脚本一次读取最多 100 条，再在客户端分页；每页可选 20、30、50 或 100 条。实际可见条目数取决于上游数据、有效影视标识和去重结果。

## 宿主与数据处理

- 预置 TMDB 脚本优先使用原公开目录线路，超时 10 秒；HTTP 错误或无效列表时，回退到 Yfuse 宿主通道，超时 18 秒。两个通道合计处于模块的 30 秒预算内。公开线路不接收认证头，原应用专用参数及认证查询参数会被移除。
- 无显式 `apiKey` 的宿主 TMDB 请求复用应用的 `tmdb-http` 客户端，遵循现有登录态账户代理和直连回退规则。提供显式 `apiKey` 的外部组件继续使用固定 TMDB 主机的独立请求通道。
- 账户通道仅接收公开影视资料的相对路径和 GET 请求。脚本不能传入账号查询凭据；宿主不转发脚本自定义认证头，也不把账户代理的响应头和内部网络异常交给脚本。
- 网络响应继续限制为 4 MiB，单次请求最多 30 秒。安装预览不请求网络、不写组件存储。
- 原 TMDB 脚本可能把人物趋势识别成剧集。适配版过滤人物、无效 TMDB ID、缺失标题的条目，并补齐新闻、脱口秀、战争政治剧的剧集分类路由。
- 推荐脚本先验证影视类型和 TMDB ID、去重，再分页，避免无效条目造成分页空洞。只允许已登记榜单路径，并校验页码、每页数量和星期。
- HTTP 错误、格式错误会显示为加载失败；上游合法的空列表仍显示为空榜单。

## 首次安装、升级与个人设置

`WidgetDatabase.bundledDigests` 保存预置脚本的上次版本摘要；`removedBundledWidgets`、`removedBundledPages` 单独保存主动删除意图，`bundledStateVersion` 标记迁移版本。旧备份使用默认值，保持 schema 1 兼容。旧版本只有摘要时，不能确定原因的缺项保守视为主动删除，可由组件管理中的恢复入口重新添加。

1. 首次引入时，独立检查两个组件及对应页面，再原子保存有效结果；单个资源读取或解析失败不会阻断另一个组件。保留已有页面、栏目顺序、默认首页。
2. 后续升级只替换摘要仍与上次预置版本一致、来源仍为内置的脚本，并保留启停状态。个人导入或修改过的同 ID 脚本保留原样。
3. 卸载和删除页面的意图随备份保留；应用重启和预置版本更新不会擅自恢复主动删除内容。组件管理直接显示缺失的 TMDB／影视推荐，可分别添加或恢复预置页面，不覆盖已经编辑的脚本与页面。
4. 组件、页面和每页栏目不再设置固定数量上限。自动补全保留个人页面与主动删除记录；脚本或配置体积超出保护范围时显示失败说明，已有内容不受影响。
5. 预置资源、脚本检查或保存失败时，保留已有有效快照并显示提示，个人组件仍可编辑和备份。原有快照损坏时不会用预置内容覆盖它。
6. 导出/恢复会携带预置摘要和删除状态。恢复引入这些组件之前的旧备份后，当前进程立即按首次引入规则补齐组件。

## 验证范围

- `BundledWidgetRepositoryTest`：首次安装、升级、默认首页、禁用、卸载与备份恢复、个人同 ID 脚本、页面冲突、容量限制、失败原子性。
- `BundledWidgetRuntimeTest`：在实际 QuickJS 引擎中读取打包资源，检查 9 个 TMDB 模块和全部 25 个推荐榜单的调用、标识、分类、分页、异常响应，以及公开线路失败/数据无效时的有界回退。
- `WidgetTmdbHttpTest`：账户代理、未登录直连、认证隔离、相对路径约束、响应大小和取消。
- 2026-10-23 公开服务检查：25 个推荐地址全部返回 HTTP 200；IMDb 热门电影、IMDb 热门剧集、动画放送日历当时为空。五个默认推荐模块实际返回 30 / 30 / 30 / 11 / 30 条有效影视记录。
- 最终资源在线实测：9 个 TMDB 模块全部成功，除综合趋势过滤人物后为 19 条外，其余均返回 20 条有效影视记录；5 个默认推荐模块也全部成功。电视网和制作公司筛选实测分别使用 ID `213`、`2`。
- 当前电脑直连 TMDB 超时，自有服务器匿名 TMDB 请求返回 401；这些限制不影响已实测的默认公开线路。Yfuse 登录态备用通道以自动化测试验证，尚未做手机或真实登录态在线验收。相关记录位于同名审计目录。
