# 全内核输出与运行时优化（2026-10-14）

本轮按“输出可信度 → 可确认的运行时开销与恢复 → 实机基线”的顺序修改源码。覆盖 Android 的 ExoPlayer、MPV、MDK、YCore，共用 TV 代码，以及 Harmony 使用的可移植 YCore ABI。没有打包、安装应用、发布或修改版本号。

## 已落实

| 范围 | 修改 | 目的 |
| --- | --- | --- |
| Exo | 包装 Media3 的 codec adapter factory，记录成功创建的解码器 MIME 与实际隧道配置；释放时按实例清理。 | 防止 DV 输入通过 HEVC 基础层解码时被标为原生 DV；不再把隧道状态固定写成 false。 |
| Exo 音频 | 读取真实 AudioSink 播放时钟，等待推进后确认音频；flush、重新配置、释放后重新验证。忽略旧 AudioTrack 的延迟释放回调。 | AudioTrack 配置成功不能直接证明实际输出。 |
| MPV | 缓存音频输出配置，在已有进度采样中读取 audio-pts；只在证据状态变化时发布音频诊断。拖动、切轨、重载、暂停、缓冲及设备路由变化会使旧证据失效。 | 避免仅根据 current-ao、输出格式和 codec 标签认定音频/Atmos 已输出；不增加独立高频轮询。 |
| MDK | 原生事件和定时采样共用一个协程，合并事件突发；六项进度字段由一次 JNI 快照返回。 | 消除两个采样入口竞争，减少跨 JNI 调用；状态提交前核对加载代次。 |
| MDK Surface | 解绑/更换窗口清除旧首帧；解绑后的事件不能恢复首帧标志；忽略旧 SurfaceHolder 回调。 | 防止旧画面的证据跨窗口复用。 |
| YCore 音频 | 音频时间戳必须具有合理的新鲜度；倒退或往返抖动不刷新“有进展”期限。 | 避免异常 OEM 音频时钟长期占用主时钟；保持播放头和墙钟回退。 |
| 共用输出 | 释放视频时同时清除 RPU、FEL、隧道及动态范围输出标志；释放/等待音频时清除 Atmos 输出模式与路由验证。 | 源格式与当前有效输出保持分离。 |
| 共用压力策略 | 降低开销立即生效，自动省电后等待 30 秒稳定恢复；用户主动切换模式不等待旧计时器。 | 减少资源压力波动引发的播放模式反复重建。 |
| Harmony ABI | 主机显式解绑视频窗口后，屏蔽后端缓存的已渲染/DV 证据；音频状态保留。 | 统一无输出窗口时的状态约束。 |
| TV 构建 | 补齐共享导航新增 Watching 后遗漏的分支；未适配的手机在看入口转到现有 TV 媒体库。 | 修复本次扩大编译发现的已有阻塞，避免焦点请求落到不存在的导航项。 |

MDK 的输出色彩空间、独立音频渲染时钟和实际掉帧统计仍保留 Unknown/未测量。SDK 0.37 的输入信息与通用 position() 没有被冒充为这些输出事实。MPV 既有 gpu → gpu-next 映射继续保留。

## 基线工具

`scripts/playback-startup-baseline.py` 读取已有诊断 JSONL，按实际 engine、renderPath 和音/视频首个已验证输出分组，输出样本数、P50、P95、最大值和输入文件 SHA-256。少于 20 个样本标记为样本不足；缺测不计为零；恢复事件不计为新启动；重复导出的记录去重。

```powershell
python scripts/playback-startup-baseline.py diagnostic-001.jsonl `
  --device "设备型号 / Android 版本" --media-case "固定样片编号" `
  --scenario "webdav-cold" --output audit/startup-baseline.json
```

每个设备、片源和网络场景分别导出/运行，不能混合不同条件比较。指标是输出代次开始到首次已验证输出，排除引擎建立前的准备时间；也不代表启动成功率。音频现在要求时钟推进，结果还包含既有进度采样粒度，不能与以前仅记录 AudioTrack 配置成功的数值直接比较。

拖动恢复、弱网、峰值内存、温升、4K P7/FEL 持续播放仍需相同设备和样片的实际测试。此次没有生成虚构的速度或功耗提升百分比。

## 验证

验证日志保存在 `audit/kernel-optimization-20261014/`。首轮 47 项主机回归和 MDK arm64 JNI 编译通过；包含新增窗口解绑用例的 20 项可移植 ABI 用例已编译为独立 Android arm64 测试程序，在已连接设备执行成功，临时程序已移除。这验证的是可移植逻辑，不是 Harmony 系统集成。

最终扩大回归覆盖 Exo/MPV/MDK、Dolby 路由、AudioClock、输出证据、内核切换、缓冲与恢复策略：手机 56 个套件、276 项测试，TV 22 个套件、118 项测试，均零失败、零跳过。MDK arm64 JNI 编译通过，基线脚本 2 项测试通过，函数大小门禁与 `git diff --check` 通过。完整记录见同目录 `regression-tests.log` 和 `validation-summary.json`。

## 尚不能据此宣称的能力

- 没有新增 YCore 完整 P7 FEL 重建、独立 TrueHD Atmos 接收端证据或 MDK 原生杜比显示认证；这些需要真实底层实现和指定设备验证。
- 没有以单元测试替代 YCore 已定义的多芯片、多设备、连续拖动、窗口重建和 8/24 小时长播验收。
- Harmony 未生成 HAP，缺少 Cangjie/设备环境时不能宣称移植完成。
- TV 标准打包配置仍需在交付工作中与 full/MDK 要求对齐；本轮没有通过降低 TV ABI 覆盖范围来规避其固定组件与打包约束。
