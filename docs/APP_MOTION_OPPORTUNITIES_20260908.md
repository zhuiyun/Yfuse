# 动画体验补充实施记录（2026-09-08）

此前提出的五项建议均已实现。短反馈围绕用户当前操作展开，遵守页面可见性和减少动态效果设置。

| 场景 | 最终行为 | 主要实现 |
| --- | --- | --- |
| 播放器浮动提示 | 控制栏显隐时，跳过提示和聊天预览以 180 ms 平滑移动；点击区域随提示一起移动，视频与字幕位置保持稳定。快速反向时从当前位置继续，隐藏或减少动画时立即归位。 | `PlayerHintMotion.kt`、`PlayerControls.kt` |
| 搜索状态交接 | 加载、错误、空状态与结果交接采用 150 ms 淡入。使用同一棵结果列表；保留结果的刷新、分页和增量到达不会重播整页淡入，隐藏完成后返回直接显示。 | `SearchResultsHandoff.kt`、`SearchScreen.kt` |
| 列表补位 | 下载列表和服务器列表接入已有的局部条目动画，删除、筛选和排序通过稳定业务 ID 跟踪位置。切换默认服务器保留同一服务器的身份。 | `DownloadsScreen.kt`、`ServersTabScreen.kt` |
| 刷新完成反馈 | 根据本次健康检查和统计请求的真实结果，区分全部成功、部分失败、全部失败、取消和空列表。请求代次隔离旧反馈，后台完成不在返回时补播。 | `ServerRefreshState.kt`、`ServersTabComponent.kt`、`ServerHealthMonitor.kt` |
| 说明面板 | 搜索服务器说明与账户加密说明共享 160 ms 展开、收起和箭头旋转；正文仅保留一份，收起完成后移除，快速反向连续衔接。 | `DisclosureMotion.kt`、`SearchScreen.kt`、`AccountSettingsScreen.kt` |

## 列表与图片加载

列表需要明确的加载状态，但已有内容、滚动和分页应保持稳定。保留现有骨架反馈并让隐藏页面停止脉冲；搜索仅在状态交接时淡入，避免批量卡片逐个入场造成等待和额外动画开销。

图片沿用轻量加载反馈：密集海报使用 180 ms 淡入，较大的艺术图保留已有 400 ms 揭示效果。新增统一的 `ImageRevealMotion.kt`，每个图片请求拥有独立进度；新请求从未显示状态开始，内存缓存命中、隐藏页面、关闭动画或减少动画时直接显示。已经加载的图片在返回页面时不重播。进度在绘制层读取，避免逐帧重组宿主。

真机图片回归验证动画时钟、策略切换和请求切换；内存缓存通过既有 Coil `MEMORY_CACHE` 标记接入，本次没有把网络下载或磁盘缓存命中率作为测试结论。
